## B-001 — Saved searches / bookmarks

**User story:** As a user, I pin STIGs, rules, and search queries so I return without retyping.

**Design**
- `localStorage` key `stigref-bookmarks-v1`
- Types: `{ type: 'rule'|'stig'|'query', id|query, title, savedAt }`
- UI: star on rule/STIG; “Saved” page or drawer on home
- Cap ~100 items; export/import JSON optional later (ties B-052)

**Acceptance**
- [ ] Star toggles persist across reload  
- [ ] Open bookmark navigates correctly with base `/stigref/`  
- [ ] No server/account  

**Depends:** none · **Size:** M

---

## B-002 — Shareable search URLs

**User story:** I paste a URL in a ticket; colleague sees the same query and filters.

**Design**
- Query params: `q`, `vendor`, `role`, `severity`, `tag`, `type` (stig|rule), `kev` (later)
- Router reads `location.search` on home (and optional `/search` route)
- `navigate` updates history (replaceState while typing debounced; pushState on submit)

**Acceptance**
- [ ] `/stigref/?q=SV-253284` runs search on load  
- [ ] Changing filters updates URL  
- [ ] Back button restores prior query  

**Depends:** none · **Size:** S · **Priority:** do first

---

## B-003 — Rule comparison

**User story:** Compare check/fix/CCI/Intune between two rules (or two versions later).

**Design**
- Route: `/compare?a=SV-…&b=SV-…`
- Fetch both rule JSON; side-by-side columns; highlight text diff for check/fix (simple line diff)
- Entry: “Compare…” from rule page (pick second via search modal)

**Acceptance**
- [ ] Two rules load; empty/error states  
- [ ] Shareable compare URL  
- [ ] Works when one rule missing  

**Depends:** B-002 helpful · **Size:** L

---

## B-004 — Related rules

**User story:** From a rule, jump to same group, shared CCI, shared CSP, or similar title.

**Design**
- Build-time: optional `data/rules/related/{id}.json` **or** client-side from search index fields  
- v1 client-side: filter search docs by same group_id / cci / cspId if stored on index  
- UI: “Related” section on rule page (max 10)

**Acceptance**
- [ ] At least group_id + CCI related lists when data present  
- [ ] No infinite spinner if none  

**Depends:** richer search docs (add `group_id`, `ccis` to index if missing) · **Size:** M

---

## B-005 — Copy packs

**User story:** One click copies the format I need for tickets or Intune.

**Design**
- Expand CopyButton menu / dropdown on rule page:  
  - Citation (exists)  
  - Markdown block  
  - Check only / Fix only  
  - All OMA-URIs (from intune suggestions)  
  - Intune suggestions JSON  
- Shared formatters in `lib/copy.ts`

**Acceptance**
- [ ] Each pack copies non-empty, plain text/markdown  
- [ ] Toast on success  

**Depends:** none · **Size:** S

---

## B-006 — Keyboard-first UX

**User story:** Power users navigate without the mouse.

**Design**
- `/` focus search (if not in input)  
- `j` / `k` move result highlight; `Enter` open  
- `c` copy citation on rule page  
- `?` shortcut cheatsheet modal  
- Respect `prefers-reduced-motion`; don’t capture when typing in inputs

**Acceptance**
- [ ] Shortcuts documented in About or `?`  
- [ ] No breakage of normal typing  

**Depends:** B-002 for consistent result list · **Size:** M

---

## B-007 — Print / PDF-friendly rule view

**User story:** Print a rule for a CAB or audit folder.

**Design**
- `@media print` CSS: hide nav/theme/toasts; expand check/fix; show URL and content date  
- Optional `?print=1` auto-print

**Acceptance**
- [ ] Print preview is readable single column  
- [ ] Deep link still in footer  

**Depends:** none · **Size:** S

## B-008 + B-026 — Severity / CCI filters & faceted search

**User story:** Narrow results by severity, type, vendor, role, has-Intune, (later has-KEV).

**Design**
- Extend search documents at build with: `severity`, `ccis[]`, `vendor`, `roles`, `hasIntune`, `hasCve`  
- MiniSearch filter function **or** prefilter docs then search  
- UI chip row + dropdowns on home; sync to URL (B-002)

**Acceptance**
- [ ] Filter + query compose correctly  
- [ ] URL round-trip  
- [ ] Performance acceptable on full index (consider Web Worker B-040 next)

**Depends:** B-002 · **Size:** M

**Acceptance**
- [ ] Feature flag or map list in config

**Depends:** B-011 recommended first · **Size:** L

## B-014 — Multi-option ranking

**User story:** When multiple CSPs are listed, the preferred native option is first.

**Design**

- Badge “Preferred” on first native high/medium  
- Keep all options visible (decision 2B)

**Acceptance**
- [ ] Deterministic order  
- [ ] Preferred label only when multiOption  

**Depends:** none · **Size:** M

## B-018 — CSP catalog refresh job

**User story:** Quarterly build refreshes CSP index, not only STIG XCCDF.

**Design**
- Script `scripts/stigref_build/refresh_csp_catalog.py`

  - Outputs: updated `catalog_seed.json` + changelog of new ids  
- Runbook section in INTUNE_CSP.md  
- Full Learn scrape is **out of scope**; prefer DDF/area lists + curated registry paths

**Acceptance**
- [ ] Documented quarterly steps next to STIG zip ingest  
- [ ] Catalog version bumps in meta or csp/catalog.json  

**Depends:** none · **Size:** L
